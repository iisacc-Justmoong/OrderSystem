# 주문 업무 흐름

이 문서는 포트폴리오 설명에서 강조할 주문 처리 계약을 정리한다.

## 생성

1. 고객이 존재해야 한다.
2. 주문 항목은 하나 이상이어야 하며 수량은 1 이상이어야 한다.
3. 상품은 존재하고 판매 가능한 상태여야 한다.
4. 재고는 주문 수량 이상이어야 한다.
5. 주문 총액은 서버 DB의 상품 가격으로 계산한다.
6. 주문 번호를 생성하고 주문 및 주문 항목을 저장한다.
7. 재고를 조건부 업데이트로 차감한다.
8. `InventoryTransactions`에 음수 재고 변동을 기록한다.
9. `OrderStatusHistories`에 최초 `Pending` 상태 이력을 기록한다.
10. 전체 과정을 하나의 트랜잭션으로 저장한다.

## 상태 전이

허용 상태 전이는 `Pending -> Confirmed -> Preparing -> Shipped -> Delivered`이다. `Delivered`, `Cancelled`는 종료 상태다.

## 취소

`Pending`, `Confirmed` 상태의 주문만 취소할 수 있다. 취소 시 주문 상태를 `Cancelled`로 변경하고 주문 항목 수량만큼 재고를 복구한다. 배송 이후 취소는 이 프로젝트 범위에서는 허용하지 않으며, 실제 업무에서는 반품 프로세스로 분리한다.

## 결제

결제는 주문과 분리된 `Payments` 장부에 저장한다. 실제 PG 연동은 하지 않지만 결제 수단, 결제 상태, 금액, 결제 완료 시각을 보존한다. 주문이 생성되었지만 결제가 실패하거나, 이후 환불 이력이 생길 수 있으므로 주문 헤더에 결제 정보를 직접 섞지 않는다.

## 테스트 기준

서비스 테스트와 REST API 통합 테스트는 다음 회귀를 고정한다.

- 주문 생성 시 재고가 차감되고 주문 번호와 주문 시점 단가가 보존된다.
- 주문 생성 시 재고 이력과 최초 주문 상태 이력이 기록된다.
- 재고 부족 주문은 주문을 만들지 않고 재고도 바꾸지 않는다.
- 취소 가능한 주문은 재고를 복구하고 복구 이력을 기록한다.
- 배송된 주문은 취소할 수 없고 차감된 재고가 유지된다.
- 허용되지 않은 상태 전이는 거부된다.
- 상태 변경은 `OrderStatusHistories`에 남는다.
- 결제 기록은 `Payments`에 주문과 분리해 저장된다.
- 주문 상태 enum은 DB에 정수 코드로 저장된다.
- Swagger 문서와 주요 REST 엔드포인트가 HTTP 경로로 동작한다.
- 배송 후 취소와 잘못된 상태 전이는 `409 Conflict`로 응답한다.
- SQL Server용 `database/` 스크립트 세트는 스키마, 샘플 데이터, 저장 프로시저, 리포트 쿼리를 실행 순서대로 제공한다.
